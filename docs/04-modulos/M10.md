# M10 · Comunidad y moderación

**Propósito:** Compartir recetas y comentarios con seguridad.

**Alcance:** Publicar receta, comentar, calificar, reportar, moderación (Studio), soporte (tickets).

**Pantallas:** Comunidad, Reportar, Soporte.

**Datos (tablas/vistas):** `recipes`(author_id), `recipe_comments`, `content_reports`, `support_tickets`, `user_roles`.

**Contratos (RPC / Edge / Auth):** Lecturas/escrituras con RLS; triggers de auto-moderación.

**Reglas clave:** Requiere `community_sharing`; 3 reportes ocultan/devuelven a revisión.

**Límites:** Sin panel propio; autores anónimos; sin mensajería.

### US-154 · Solicitar consentimiento explícito para funciones de comunidad
- Backend: `accept_consent(doc community_sharing)`; trigger `require_community_consent`; `revoke_consent('community_sharing')` borra comentarios y despublica recetas propias; vista `my_pending_consents`.
- Pantallas: Diálogo de consentimiento comunitario (primer uso de comentar/compartir)
- Notas/límites: Aceptar es independiente de usar la app. Revocar tiene efectos destructivos: avisar antes.
- Ficha completa: `05-historias-de-usuario/E5-*.md` (ancla `#us-154`)

### US-167 · Publicar receta propia o adaptación
- Backend: `recipes.author_id` no nulo; estados `draft → in_review → published | rejected`; las mismas reglas de publicación; requiere consentimiento de comunidad.
- Pantallas: Receta (publicar)
- Notas/límites: Las recetas de comunidad NO pasan por revisión nutricional (se indica en la UI). Revisión de moderación sí.
- Ficha completa: `05-historias-de-usuario/E5-*.md` (ancla `#us-167`)
