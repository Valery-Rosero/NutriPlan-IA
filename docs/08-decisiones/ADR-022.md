# ADR-022 · Arquitectura de la app: features por capas, puertos y adaptadores

**Estado:** Aceptada (13-oct-2026). Concreta ADR-012.

## Contexto y decisión
La app debe crecer de 12 módulos sin enredarse ni amarrarse a Supabase. Cada feature (`src/features/<feature>/`) tiene cuatro capas con dependencias en una sola dirección (`ui → application → domain ← data`):

| Capa | Contiene | Depende de |
|---|---|---|
| `domain/` | Tipos, **puertos** (interfaces `*Repository`), reglas puras (`requiredConsents`, `createLoginThrottle`), esquemas Zod | Nada (ni React ni Supabase) |
| `data/` | **Adaptadores** que implementan los puertos con Supabase; traducen errores externos a `AppError` (capa anticorrupción) | `domain`, `core` |
| `application/` | **Casos de uso** como hooks de TanStack Query (`useSignUp`, `useRequiredConsents`), fábricas de claves de consulta, observador de sesión | `domain`, `di` |
| `ui/` | Pantallas y componentes de la feature | `application`, `shared/ui` |

Transversales: `core/` (errores de dominio, formato, sin dependencias), `infrastructure/` (cliente Supabase, i18n, caché, logger, env), `shared/` (sistema de diseño y tema), `di/` (contenedor de dependencias). `src/app/` solo tiene rutas de una línea que reexportan pantallas.

**Patrones usados y dónde:**
- **Repository + Ports & Adapters:** `AuthRepository` → `SupabaseAuthRepository`, igual para legal y cocina.
- **Inyección de dependencias por contexto:** `di/services.tsx` + raíz de composición `di/create-services.ts`; las pruebas inyectan dobles (`src/test/fakes.tsx`).
- **Anti-Corruption Layer:** `mapAuthError` y `toAppError`; la UI solo conoce `ErrorCode` y muestra `errors.<code>` de i18n.
- **Observer:** `AuthRepository.onSessionChange` → `SessionProvider`.
- **Policy / Specification:** `requiredConsents` decide qué documentos bloquean la entrada; `createLoginThrottle` con reloj inyectable.
- **Query Key Factory:** `legalKeys`, `cookingKeys` centralizan nombres e invalidaciones.
- **Guardas de navegación:** `Stack.Protected` en `app/_layout.tsx` (sin sesión → consentimientos → app).

## Alternativas consideradas
Carpetas por tipo (`components/`, `hooks/`, `services/`): se dispersa cada feature. Redux/clean architecture con clases de caso de uso: más código ceremonial sin beneficio frente a hooks.

## Consecuencias
Cambiar de proveedor o probar sin red es implementar un puerto. Regla para revisar PR: `domain/` nunca importa React, Supabase ni `infrastructure/`; las pantallas nunca importan `infrastructure/supabase`.
